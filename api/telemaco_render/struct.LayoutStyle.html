Expand description

The subset of CSS that influences box layout. Expanded in later phases.

Fields§

§display: Display§direction: Option<Direction>

Computed inline base direction. None is the inherited specified state before the DOM top-down pass resolves it.

§container_type: ContainerType

Computed CSS container-type (not inherited).

§container_names: Vec<String>

Computed CSS container-name; empty represents none (not inherited).

§internal_flex_container: bool

True when display:flex is only an internal stand-in for native HTML layout such as table cells, rather than the computed CSS display. Descendants are not CSS flex items in these containers.

§legacy_center: bool

The HTML UA sheet’s vendor text-align behavior for <center>. Unlike ordinary text-align:center, it also centers fixed-width block descendants while leaving auto-width blocks fill-available.

§width: Dimension§width_fit_content: bool

The preferred inline size is the intrinsic fit-content keyword.

Taffy’s box-size dimension cannot represent intrinsic sizing keywords, so width remains Auto while the DOM layout convergence pass applies the CSS shrink-to-fit formula from min/max-content measurements.

§height: Dimension§box_sizing: BoxSizing

Which box edge width/height and min/max sizes describe. CSS starts at content-box; many modern reset sheets opt into border-box.

§width_set: bool

Whether width/height was set by an author rule (including an explicit auto). Presentational width/height HTML attributes are a lower priority than author CSS, so they apply only when these are false; an explicit width:auto must still suppress a width="408" attribute so the element keeps its aspect-ratio size instead of the intrinsic one.

§height_set: bool§min_width: Dimension§min_height: Dimension§max_width: Dimension§max_height: Dimension§size_expressions: [Option<String>; 6]

Deferred CSS math expressions for width, height, min-width, min-height, max-width, and max-height. Functional lengths can depend on the actual viewport, containing block, or computed font size and cannot be safely collapsed to pixels during stylesheet parsing.

§aspect_ratio: Option<f32>

aspect-ratio as width/height, or an image’s intrinsic ratio resolved at layout. Lets a replaced element (or a padding-box card) derive the missing dimension from the given one, so a width:100% image gets a real height instead of collapsing to zero.

§aspect_ratio_is_intrinsic: bool

Whether the preferred ratio came from decoded intrinsic media and therefore applies to the content box regardless of box-sizing.

§intrinsic_size: Option<(f32, f32)>

Fetched intrinsic CSS-pixel size for a replaced element. Kept alongside aspect_ratio so its taffy leaf can contribute a real min/max-content size when percentage dimensions are resolved through an auto-sized wrapper (img { width:100%; height:auto }).

§aspect_ratio_is_mapped: bool

The current ratio came from HTML width/height presentation hints (<img> or its selected <picture><source>), rather than authored CSS. A decoded image’s natural ratio replaces this provisional ratio.

§margin: Edges§margin_auto: [bool; 4]

Which margin sides are auto (top, right, bottom, left). margin: 0 auto / margin-inline: auto centering needs a real Auto margin, which the f32 margin cannot express; this flag drives it at taffy mapping.

§margin_percent: [Option<f32>; 4]

Percentage margin per side (top, right, bottom, left) as a 0..1 fraction, None when the side is a fixed length. Like padding, every side resolves against the containing block’s WIDTH; the f32 margin cannot carry a percentage, so this is resolved to px during dom::layout_dom’s top-down pass once the containing-block width is known.

§margin_relative: [Option<Dimension>; 4]

Font- and viewport-relative margin lengths (top, right, bottom, left). These retain their unit until the top-down pass knows the element font size, root font size, and viewport dimensions.

§margin_expressions: [Option<String>; 4]

Deferred calc()/min()/max()/clamp() margin expressions.

§padding: Edges§padding_percent: [Option<f32>; 4]

Percentage padding per side (top, right, bottom, left) as a 0..1 fraction, None when the side is a fixed length. All four sides resolve against the containing block’s WIDTH (per CSS, including top/bottom): this is the responsive aspect-ratio-box trick (padding-top:56.25% reserves a 16:9 area). The percentage remains typed through Taffy layout so flex/grid min/max sizing can establish the final containing-block width first. dom::layout_dom writes Taffy’s resolved used pixels back into padding before paint and geometry consumers inspect the computed layout.

§padding_relative: [Option<Dimension>; 4]

Font- and viewport-relative padding lengths (top, right, bottom, left), resolved alongside margin_relative during the top-down pass.

§padding_expressions: [Option<String>; 4]

Deferred calc()/min()/max()/clamp() padding expressions.

§border: Edges§border_model: BorderModel

Specified border state. border above is the derived used-width view consumed by layout; it is zero on none/hidden sides while this model retains their specified widths for later cascade declarations.

§outline: OutlineModel

Outline paint state. It deliberately has no counterpart in Taffy: outlines never contribute to box geometry.

§clip_path: Option<ClipPathPolygon>

clip-path: polygon(...), resolved against the final border box at paint time. None is the computed none value.

§background_color: Option<[u8; 4]>

RGBA for the paint step. Parsed always (cheap), used only with paint.

§background_gradient: Option<(f32, Vec<([u8; 4], Option<f32>)>)>

linear-gradient(...) background: (angle in degrees clockwise from 12 o’clock per CSS, list of (rgba, optional 0..1 stop position)). Modern hero sections use gradients heavily; without this they paint white.

§background_radial_gradient: Option<((f32, f32), Vec<([u8; 4], Option<f32>)>)>

First radial-gradient(...) layer: center in box-relative fractions and color stops. It is painted below the first linear layer, matching the common linear-gradient(...), radial-gradient(...) hero pattern.

§background_conic_gradient: Option<(f32, (f32, f32), Vec<([u8; 4], Option<f32>)>)>

conic-gradient(...) background. The angle is the CSS from angle, the center is a fraction of the border box, and stops are normalized during paint. Conic gradients commonly provide the color source for a repeated SVG mask in modern hero artwork.

§background_gradient_layers: Vec<BackgroundGradientLayer>

Every parsed gradient in authored background-layer order. The legacy single-kind fields above remain populated for mask/text fast paths.

§background_image: Option<String>

The first url(...) reference from background/background-image (gradients and repeat keywords in the same shorthand are ignored: we paint the referenced image, not the gradient layer).

§background_size: Option<(f32, f32)>

background-size, in px, when given as explicit length(s) (a bare 10px applies to both axes, matching how small square icons are almost always sized).

§background_size_expression: Option<String>

Raw one/two-axis background-size expression, retained for paint-time resolution against the final owner box (calc(100% - 2rem) auto).

§background_size_fit: Option<ObjectFit>

Keyword background-size behavior. None is CSS auto, which uses the image’s intrinsic dimensions rather than stretching it to the box.

§background_position: BackgroundPosition

background-position, retained as a length-plus-percentage per axis. Percentages apply to the leftover space after resolving explicit, intrinsic, cover, or contain size.

§background_repeat: Option<(bool, bool)>

Explicit (repeat-x, repeat-y) choice. None is the CSS initial repeat in both axes.

§background_origin: BackgroundOrigin

Geometry longhands retained independently: gradients and images are authored in background-origin, while background-clip only limits which portion becomes visible.

§background_clip: BackgroundClip§background_clip_text: bool

background-clip: text / -webkit-background-clip: text: the background paints only through the element’s glyphs, not as a filled box. Combined with a transparent text color this is the common gradient-text technique (hero headings, buttons like astro.build’s “Get Started”); without honoring it those labels paint invisible. Consumed in the text paint path (inline::TextEngine fills glyphs from the background; paint suppresses the box fill so the gradient does not paint as a rectangle).

§mask_image: Option<String>

mask-image/-webkit-mask-image: url(...): the ubiquitous “colored, scalable icon” pattern (an SVG shape used as a stencil, tinted by background-color/color instead of carrying its own colors). Without this, every such icon paints as a solid filled square.

§mask_size: Option<(f32, f32)>

Explicit mask-size / -webkit-mask-size in CSS px.

§mask_repeat: Option<(bool, bool)>

Explicit (repeat-x, repeat-y) choice. None retains the CSS default (repeat on both axes) when an explicit tile size exists, while preserving the legacy fill-box fallback for unsized icon masks.

§color: Option<[u8; 4]>

Foreground (text) color for the paint step.

§svg_fill: Option<String>

Computed SVG presentation properties supplied by author CSS. Inline SVG is serialized into a standalone document for resvg; without carrying these values across that boundary, stylesheet-driven icons and text lose their fill/stroke and can become completely invisible.

§svg_stroke: Option<String>§svg_stroke_width: Option<String>§border_color: Option<[u8; 4]>

Compatibility mirror for uniform border colors. New code should use border_model.colors; this remains for programmatic LayoutStyle users.

§color_scheme_dark: bool

Used color scheme for CSS Color 5 light-dark(). The renderer’s current user preference is light; an inherited color-scheme: dark subtree switches this to true, while normal, light, or a list that permits light keeps the light scheme.

§font_size: Option<f32>§font_size_raw: Option<Dimension>

font-size given in a font/viewport-relative unit, resolved to font_size (px) during the inheritance pass against the parent and root font-sizes. None when font-size was absolute or unset.

§font_size_expression: Option<String>

Deferred functional font-size (clamp(), min(), max(), calc()). These expressions must see the live viewport and parent font size; eagerly treating 9vw as the number 9 made responsive headings pin to the minimum arm of their clamp.

§letter_spacing: Option<f32>

Computed letter-spacing in CSS pixels. This inherited property is resolved top-down because em is relative to the element’s own computed font size while rem and viewport units need live context.

§letter_spacing_raw: Option<Dimension>

Non-pixel letter-spacing retained until the inheritance pass.

§letter_spacing_expression: Option<String>

Deferred functional letter-spacing (calc(), min(), clamp()).

§letter_spacing_non_normal: Option<bool>

Whether the computed value came from a non-normal declaration. Keeping this provenance distinguishes an explicit zero from the normal initial value while resolving the inherited property.

§font_weight: Option<String>

Specified CSS font weight during cascade (1..1000, bolder, or lighter), normalized to its numeric computed value by the inheritance pass before layout and shaping.

§font_family: Option<String>

The computed font-family list, lowercased. Inherited. The text engine resolves it to a bundled face (Liberation Sans/Serif/Mono) the way Chromium picks a generic family on this host.

§font_optical_sizing: Option<FontOpticalSizing>

Computed inherited font-optical-sizing. None during cascade means inherit; the top-down pass resolves every element to Some.

§font_variation_settings: Option<Vec<FontVariationSetting>>

Computed inherited font-variation-settings. None during cascade means inherit, while Some(Vec::new()) is the normal initial value.

§text_align: Option<AlignItems>

Inherited text-align, represented with the matching horizontal alignment keywords. Kept separate from flex/grid align-items: using one field for both made text-align:left shrink-wrap flex children.

§text_indent: Option<Dimension>

Computed inherited text-indent. Font/viewport-relative lengths are resolved to pixels during the top-down inheritance pass; percentages remain typed until the final inline-formatting-context width is known. None during cascade means inherit, while the root resolves to the initial zero length.

§align_items: Option<AlignItems>§justify_items: Option<JustifyItems>§align_self: Option<AlignSelf>§justify_self: Option<JustifySelf>§align_content: Option<AlignContent>§flex_direction: Option<FlexDirection>§flex_wrap: Option<FlexWrap>§justify_content: Option<JustifyContent>§flex_grow: Option<f32>§flex_shrink: Option<f32>§order: i32

Flex/grid item order. The formatting algorithm consumes children in order-modified document order, with source order breaking ties.

§flex_basis: Dimension

flex-basis (longhand, or the length in a flex: shorthand). Auto is the default. Fixed-basis sidebars/columns (flex: 0 0 260px) collapse to content width without it.

§grid_template_columns: Vec<GridTemplateComponent<String>>§grid_template_rows: Vec<GridTemplateComponent<String>>§grid_auto_columns: Vec<TrackSizingFunction>

Track sizing functions for columns created outside the explicit grid. An empty list is the CSS initial auto value: taffy supplies one automatic implicit track and cycles a non-empty authored list.

§grid_auto_rows: Vec<TrackSizingFunction>

Track sizing functions for rows created outside the explicit grid.

§grid_template_columns_subgrid: bool

grid-template-columns: subgrid. Taffy has no native subgrid track component, so dom resolves the safe full-span column subset after measuring the non-subgridded ancestor’s intrinsic track contributions.

§grid_auto_flow: Option<GridAutoFlow>§grid_areas: Option<Vec<Vec<String>>>§grid_area_name: Option<String>§grid_column: Option<Line<GridPlacement>>§grid_row: Option<Line<GridPlacement>>§grid_col_line_names: Option<HashMap<String, i16>>

[line-name] -> 1-based grid line number, parsed from grid-template-columns/-rows. taffy has no native named-line support, so children placed by name (grid-column: content-start / content-end, widely used by the Guardian and other editorial grids) are resolved to numeric lines against these maps in dom::resolve_grid_areas.

§grid_row_line_names: Option<HashMap<String, i16>>§grid_column_raw: Option<String>

Raw grid-column/grid-row value when it references a named line (so it cannot be resolved to a taffy::Line until the parent’s line-name map is known). Resolved in the same later pass; numeric/span values still fill grid_column/grid_row directly at cascade time.

§grid_row_raw: Option<String>§column_gap: Option<f32>§row_gap: Option<f32>§column_gap_expression: Option<String>

Deferred gap values. Font- and viewport-relative units cannot be converted until the element’s computed font-size and the live viewport are known; eagerly treating rem as 16px breaks pages that customize the root font-size.

§row_gap_expression: Option<String>§column_count: Option<u16>§break_inside_avoid: bool

break-inside: avoid makes this box an atomic balancing unit. The current box-level multicol implementation cannot fragment the inside of a child yet, but retaining the computed value makes that limitation explicit and lets the balancing path distinguish authored break avoidance as finer-grained fragmentation is added.

§border_spacing: Option<(f32, f32)>

border-spacing: <horizontal> <vertical>? (or the cellspacing attribute). Only meaningful on a <table>; taffy has no native table display mode, so dom::propagate_border_spacing distributes this down as the table’s own row gap and each descendant <tr>’s column gap.

§border_collapse: Option<bool>

Computed border-collapse. This property is inherited; None means no value was specified on this node yet and is resolved top-down before table construction. The collapsed-border conflict/paint model is still approximate, but collapsed tables must at minimum contribute no border-spacing to their geometry.

§position: Option<Position>§position_fixed: bool

Distinguishes fixed from absolute; both map to taffy’s absolute layout mode, but fixed boxes use the initial containing block.

§position_sticky: bool

Distinguishes sticky from ordinary relative positioning. Sticky boxes remain in normal flow; their insets constrain a scroll-time translation and therefore must not be applied as taffy relative offsets.

§inset: [Option<Dimension>; 4]§inset_expressions: [Option<String>; 4]

Deferred functional inset expressions in top/right/bottom/left order.

§overflow_hidden: bool

overflow/-x/-y other than visible: clips this element’s descendants to its border box during paint. This is what makes the ubiquitous “visually-hidden but accessible” pattern (a 1x1 absolutely-positioned, clipped box used for skip-links and screen-reader-only labels) actually invisible instead of painting its text wherever it lands.

§overflow_clip_x: bool

Independent computed overflow clips. overflow_hidden remains the aggregate compatibility/BFC flag; paint and automatic minimum sizing must consult the relevant axis.
